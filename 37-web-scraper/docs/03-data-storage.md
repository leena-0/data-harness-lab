# 03. 데이터 저장 설계

## 저장 위치와 형식

- 기본 데이터베이스: `data/processed/books.db`
- 테이블: `books`
- CSV 내보내기: `data/processed/books.csv`
- 생성된 DB와 CSV는 Git에 포함하지 않고 디렉터리의 `.gitkeep`만 관리한다.

가격은 부동소수점 오차를 피하기 위해 두 자리 소수 문자열(예: `"12.34"`)로 저장한다. 수집 시각은 UTC 오프셋을 포함한 ISO 8601 문자열로 저장한다.

## 스키마와 제약 조건

`upc`를 기본키로 사용한다. 필수 필드는 `NOT NULL`이며, 빈 문자열·평점 범위·재고 수량·HTTPS URL은 SQLite의 `CHECK` 제약 조건으로 한 번 더 보호한다. 상품 설명만 `NULL`을 허용한다.

주요 제약 조건은 다음과 같다.

- `upc`: 비어 있지 않은 기본키
- `rating`: 1 이상 5 이하의 정수
- `stock_count`: 0 이상의 정수
- `image_url`, `product_url`: `https://`로 시작하는 문자열
- `description`: 선택 필드

## 중복 처리

동일한 UPC가 다시 수집되면 새 행을 추가하지 않고 `ON CONFLICT ... DO UPDATE`로 최신 값과 수집 시각을 갱신한다. 따라서 크롤러를 재실행해도 같은 상품이 중복되지 않는다.

## 트랜잭션과 실패 처리

- 정상 처리된 아이템은 기본 100건마다 커밋한다.
- 크롤러가 정상 종료되면 남은 아이템을 커밋한다.
- 필드 누락이나 SQLite 오류가 발생하면 현재 미커밋 배치를 롤백하고 오류를 다시 발생시켜 저장 실패를 숨기지 않는다.
- 이전에 커밋된 배치는 유지한다.

파서의 데이터 검증 실패는 해당 상품만 건너뛰지만, 데이터베이스 연결·스키마·쓰기 실패는 실행을 실패로 처리한다.

## CSV 내보내기

다음 명령은 DB 전체를 UPC 순으로 정렬해 UTF-8 CSV로 저장한다.

```bash
cd 37-web-scraper
source .venv/bin/activate
python scripts/export_data.py
```

`--database`와 `--output`으로 경로를 바꿀 수 있다. 내보내기는 같은 디렉터리에 임시 파일을 완성한 뒤 결과 파일을 교체하므로, 작성 중인 불완전한 CSV가 최종 경로에 남지 않는다.

## 테스트 범위

- 테이블 생성과 삽입
- 동일 UPC 갱신 및 서로 다른 UPC 분리
- 평점·재고 제약 조건
- 실패한 현재 배치 롤백과 이전 커밋 보존
- CSV 헤더, UPC 정렬과 행 개수

테스트에서는 실제 프로젝트 DB 대신 임시 디렉터리의 SQLite 파일을 사용한다.
