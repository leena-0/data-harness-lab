# 00. 요구사항과 수집 범위

## 1. 실습 목적

웹 스크래핑 연습용 사이트인 [Books to Scrape](https://books.toscrape.com/)에서 도서 상품 정보를 수집하고, 검증한 데이터를 SQLite에 중복 없이 저장하는 스크레이퍼를 만든다.

이번 실습은 단순히 HTML을 읽는 데서 끝나지 않고 다음 과정을 재현 가능하게 경험하는 것을 목표로 한다.

- 수집 대상과 범위를 명시한다.
- 목록에서 상세 페이지를 발견하고 전체 페이지를 순회한다.
- 필요한 필드를 일관된 타입으로 변환하고 검증한다.
- 같은 상품을 다시 수집해도 중복되지 않도록 저장한다.
- 대상 사이트에 불필요한 부하를 주지 않도록 요청을 제한한다.
- 실패와 페이지 구조 변경을 로그와 테스트로 확인할 수 있게 한다.

## 2. 대상 사이트

| 항목 | 결정 |
|---|---|
| 사이트 | Books to Scrape |
| 시작 URL | `https://books.toscrape.com/` |
| 허용 도메인 | `books.toscrape.com` |
| 사이트 성격 | 웹 스크래핑 연습용 데모 사이트 |
| 기준 확인일 | 2026-09-29 |

기준 확인일 현재 시작 페이지에는 전체 1,000개 상품, 페이지당 20개 상품, 총 50페이지가 표시된다. 이 숫자는 테스트의 고정 상수로 사용하지 않고, 크롤러는 다음 페이지 링크가 없어질 때까지 순회해야 한다. 실제 구조와 접근 정책은 2단계의 `01-target-analysis.md`에서 다시 확인한다.

## 3. 수집 범위

### 포함 범위

- 시작 페이지에서 접근 가능한 전체 상품 목록 페이지
- 각 목록에서 발견한 모든 상품 상세 페이지
- 목록 페이지의 다음 페이지 링크를 이용한 페이지네이션
- 상세 페이지에서 제공하는 도서 정보
- 수집 결과의 SQLite 저장
- 저장된 데이터의 CSV 내보내기

### 제외 범위

- JavaScript 실행이 필요한 페이지 렌더링
- 로그인과 사용자 세션
- 장바구니 및 구매 기능
- 프록시, IP 회전과 차단 우회
- CAPTCHA 또는 기타 접근 제한 우회
- 여러 서버를 이용한 분산 크롤링
- 클라우드 배포와 스케줄러 운영
- 이메일, 메신저 등을 이용한 실시간 알림
- 개인정보 수집
- 이미지 파일 자체의 다운로드

## 4. 수집 필드

| 필드 | 의미 | 저장 타입 | 필수 여부 | 규칙 |
|---|---|---|---|---|
| `upc` | 상품 고유 식별자 | TEXT | 필수 | 공백이 없는 비어 있지 않은 값, SQLite 고유 키 |
| `title` | 도서 제목 | TEXT | 필수 | 앞뒤 공백 제거 후 비어 있으면 실패 |
| `price_gbp` | 표시 가격 | TEXT | 필수 | 통화 기호를 제거한 0 이상의 십진수 문자열 |
| `availability` | 재고 상태 원문 | TEXT | 필수 | 앞뒤와 연속 공백을 정리한 문자열 |
| `stock_count` | 재고 수량 | INTEGER | 필수 | 0 이상의 정수 |
| `rating` | 별점 | INTEGER | 필수 | 1부터 5까지의 정수 |
| `category` | 분류명 | TEXT | 필수 | 앞뒤 공백 제거 후 비어 있으면 실패 |
| `description` | 상품 설명 | TEXT | 선택 | 설명이 없으면 `NULL` |
| `image_url` | 표지 이미지 주소 | TEXT | 필수 | 절대 HTTPS URL로 정규화 |
| `product_url` | 상품 상세 주소 | TEXT | 필수 | 절대 HTTPS URL로 정규화 |
| `scraped_at` | 수집 시각 | TEXT | 필수 | UTC 기준 ISO 8601 문자열 |

가격은 부동소수점으로 저장하지 않는다. 이번 실습에서는 사이트에 표시된 통화가 GBP라는 사실을 필드명에 명시하고, `Decimal`로 검증한 문자열을 SQLite에 저장한다.

## 5. 페이지 순회 규칙

- 시작 URL에서 목록 수집을 시작한다.
- 현재 목록의 모든 상품 상세 링크를 요청한다.
- 다음 페이지 링크가 존재하면 같은 방식으로 계속 순회한다.
- `books.toscrape.com` 이외의 도메인은 방문하지 않는다.
- 상품 수와 페이지 수를 코드에 고정하지 않는다.
- 동일한 정규화 URL은 한 실행에서 중복 요청하지 않는다.
- 목록에서 발견한 상세 페이지의 처리 성공·실패 건수를 실행 결과에 기록한다.

## 6. 저장과 재수집 정책

SQLite를 기준 저장소로 사용하고, 필요할 때 전체 데이터를 CSV로 내보낸다.

- `upc`를 상품의 고유 키로 사용한다.
- 처음 발견한 UPC는 새 레코드로 삽입한다.
- 기존 UPC를 다시 수집하면 최신 필드 값과 `scraped_at`을 갱신한다.
- 동일한 UPC가 여러 행으로 저장되어서는 안 된다.
- 한 상품의 검증 실패가 이미 저장된 정상 레코드를 손상시키면 안 된다.
- CSV는 데이터 교환용 산출물이며 기준 저장소로 사용하지 않는다.
- 원본 HTML 전체를 운영 데이터로 저장하지 않는다.
- 테스트용 HTML fixture만 `tests/fixtures/`에 별도로 보관한다.

## 7. 안전한 요청 정책

- 실제 수집 전에 `robots.txt`와 사이트 이용 조건을 확인하고 2단계 문서에 기록한다.
- 동시 요청 수는 1개로 제한한다.
- 요청 사이에 최소 1초의 간격을 둔다.
- 일시적인 실패는 요청당 최대 3회 재시도한다.
- 재시도 사이에는 앞선 시도보다 긴 대기 시간을 적용한다.
- 영구적인 클라이언트 오류는 반복해서 요청하지 않는다.
- 명시적인 접근 제한, CAPTCHA 또는 차단 응답이 확인되면 실행을 중단한다.
- 의미를 식별할 수 있는 User-Agent를 사용한다.
- 로그인 정보, 쿠키 또는 개인정보를 수집하거나 저장하지 않는다.

구체적인 HTTP 상태별 재시도 범위와 User-Agent 값은 2~3단계에서 결정한다.

## 8. 데이터 품질과 오류 처리

- 필수 필드가 없거나 타입 변환에 실패한 상품은 저장하지 않는다.
- 선택 필드인 설명만 누락을 허용한다.
- 검증 실패에는 URL, 필드명과 실패 원인을 기록한다.
- 개별 상품 실패 때문에 전체 실행이 즉시 종료되지는 않지만 최종 결과는 부분 실패로 표시한다.
- 목록 페이지에서 상품 링크나 다음 페이지 링크를 찾지 못한 경우 정상 종료인지 구조 변경인지 구분할 수 있는 통계를 남긴다.
- 파서는 네트워크 없이 저장된 HTML fixture로 테스트할 수 있어야 한다.

## 9. 완료 조건

- 다음 페이지 링크가 없어질 때까지 모든 목록 페이지를 순회한다.
- 목록에서 발견한 모든 상품 상세 페이지에 대해 성공 또는 실패 결과가 기록된다.
- 성공한 상품은 정의한 필드와 타입 규칙을 만족한다.
- 같은 범위를 두 번 실행해도 UPC 중복 행이 생기지 않는다.
- 두 번째 실행에서 변경된 상품 정보는 최신 값으로 갱신된다.
- SQLite 데이터 전체를 CSV로 내보낼 수 있다.
- 요청 제한, 재시도와 도메인 제한이 설정과 테스트에서 확인된다.
- 필수 선택자가 사라지는 경우 테스트 또는 실행 통계로 감지된다.

## 10. 단계별 미결정 사항

요구사항 범위에는 영향을 주지 않지만 구현 전에 정해야 하는 항목은 다음 단계에서 결정한다.

### 2단계: 대상 분석

- `robots.txt`와 이용 조건에서 확인한 접근 가능 범위
- 목록, 상세, 다음 페이지에 사용할 CSS 또는 XPath 선택자
- URL 정규화 규칙과 페이지 구조 변경 위험

### 3단계: 크롤러 설계

- Python과 Scrapy의 구체적인 버전
- 재시도할 HTTP 상태와 backoff 설정
- User-Agent 문자열과 로그 형식

### 5~6단계: 저장과 모니터링

- SQLite 파일명과 테이블 스키마
- CSV 파일명, 정렬 순서와 인코딩
- 수집 성공 기준이 되는 통계와 구조 변경 경고 조건
