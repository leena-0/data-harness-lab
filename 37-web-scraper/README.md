# 37. Web Scraper Lab

[Harness 100의 Web Scraper](https://github.com/revfactory/harness-100/tree/main/ko/37-web-scraper/.claude)가 정의한 흐름을 참고하여, 웹에서 데이터를 안전하게 수집하고 저장·검증·모니터링하는 과정을 직접 실습합니다.

원본 하네스를 복사하는 대신 다음 과정을 한 단계씩 수행하고, 설계 판단과 실행 결과를 문서로 남깁니다.

```text
요구사항 -> 대상 분석 -> 크롤러 -> 파서 -> 저장 -> 모니터링 -> 통합 리뷰
```

## 학습 목표

- 수집 목적과 범위를 명확하게 정의한다.
- `robots.txt`, 이용 조건, 요청 부하를 고려해 안전한 수집 정책을 세운다.
- 목록과 상세 페이지를 순회하는 크롤러를 구현한다.
- HTML에서 필요한 데이터를 추출하고 타입과 필수값을 검증한다.
- 재실행해도 중복되지 않도록 데이터를 저장한다.
- 실패 재시도, 로그, 수집 통계와 구조 변경 감지를 적용한다.
- 테스트와 실행 결과를 재현 가능한 기록으로 남긴다.

## 실습 시나리오

스크래핑 연습용 도서 사이트를 대상으로 상품 목록과 상세 정보를 수집합니다. 실제 대상과 수집 필드는 1단계의 [`docs/00-requirements.md`](docs/00-requirements.md)에서 확정합니다.

현재 가정하는 범위는 다음과 같습니다.

- 목록 페이지와 페이지네이션 순회
- 상품 상세 페이지 수집
- 제목, 가격, 재고 상태, 평점, 카테고리, URL 추출
- SQLite 저장과 CSV 또는 JSONL 내보내기
- 중복 방지, 오류 재시도, 요청 속도 제한
- 파서 테스트와 HTML 구조 변경 감지

## 진행 순서

- [ ] 1단계: 요구사항과 수집 범위 정리
- [ ] 2단계: 대상 사이트 구조와 수집 정책 분석
- [ ] 3단계: 크롤러와 페이지 순회 구현
- [ ] 4단계: 파서와 데이터 검증 구현
- [ ] 5단계: 저장, 중복 제거와 내보내기 구현
- [ ] 6단계: 테스트, 재시도와 모니터링 구성
- [ ] 7단계: 통합 실행, 결과 검토와 회고

## 안전 원칙

- 허용 여부를 확인하기 전에는 실제 사이트를 수집하지 않는다.
- `robots.txt`와 사이트 이용 조건을 확인하고 기록한다.
- 요청 간격과 동시 요청 수를 제한한다.
- 로그인, CAPTCHA, 접근 제한 또는 차단 장치를 우회하지 않는다.
- 개인정보나 수집 목적에 필요하지 않은 정보는 저장하지 않는다.
- 오류가 발생하면 무한 재시도하지 않고 원인을 기록한 뒤 중단한다.

## 완료 기준

- 정의한 범위의 페이지를 빠짐없이 순회한다.
- 필수 필드가 올바른 타입으로 저장된다.
- 같은 데이터를 다시 수집해도 중복 레코드가 생기지 않는다.
- 일시적인 오류와 영구적인 오류를 구분해 처리한다.
- 선택자 또는 페이지 구조가 바뀌면 누락을 감지한다.
- 저장된 HTML fixture만으로 파서 테스트를 실행할 수 있다.
- 실행 방법, 수집 결과와 남은 한계가 문서에 기록되어 있다.
